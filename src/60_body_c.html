都是实际被问过的。答不上来的我会直说。

写死脚本只能跑一条路径。图纸换一张、软件弹个对话框，它就断了。Agent 能自己绕过去，而每一步的回读校验还能复用。代价是得先把判据定义清楚，这活儿省不掉。

能。技能里放的是流程和判据，零件参数是输入。换零件只要换图纸和尺寸表，流程不用重写。这也是把它做成 Skill 而不是一次性脚本的原因。

本机 Windows，装好对应软件并保持运行，Python 侧用 pywin32 和独立的虚拟环境。软件没启动的话 COM 连接会直接失败，这是最常见的原因。

画图和改图会，而且已经在发生。但定义需求、判断结构合不合理、公差给多少，这些还早。现在这套东西省掉的是点击和重复核对，不是判断。

因为本机多个 API 的返回值和实际结果是相反的。所以判据一律用面数、实体数、外观回读和渲染截图，不看返回值下结论。这条是被坑出来的。

可以先聊具体要自动化的那个环节。能公开的脚本我会整理到站上，其余的按需单独说。
